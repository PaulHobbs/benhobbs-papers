# Workflow Design: Paper Site Generation and Metadata Update

This document outlines the refactoring of the site generation and metadata update process using the Prefect workflow engine. The goal is to create a composable pipeline of steps that can be easily invalidated and re-run, improving efficiency and maintainability.

## Core Concept

The existing scripts (`agents/add_titles.py`, `agents/create_site.py`, `agents/site_utils.py`) will be replaced by a set of Prefect tasks and flows. Each task represents a discrete, cacheable operation. Prefect manages the execution, dependencies, and caching, allowing for efficient re-runs of specific parts of the pipeline when inputs or task code change.

## Proposed Pipeline Stages (Prefect Tasks)

The process is broken down into the following tasks:

1.  **`task_generate_initial_html`**:
    *   **Input:** PDF file path, Paper name.
    *   **Output:** Raw HTML content string.
    *   **Action:** Calls the Gemini API with the primary generation prompt (`_PROMPT`) using the PDF content.
    *   **Caching:** Cacheable based on PDF content hash and task code.

2.  **`task_fix_links`**:
    *   **Input:** Raw HTML content string, Paper name.
    *   **Output:** HTML content string with fixed Wikipedia links and markdown formatting.
    *   **Action:** Calls the Gemini API with the link-fixing prompt.
    *   **Caching:** Cacheable based on input HTML content hash and task code.

3.  **`task_run_feedback_loop`**:
    *   **Input:** Fixed HTML content string, Paper name.
    *   **Output:** Final, refined HTML content string.
    *   **Action:** Runs the iterative Gemini feedback loop using the `_FEEDBACK_PROMPT`. **Crucially, within each iteration, after receiving updated HTML from Gemini, the task will save the intermediate HTML to a temporary file and take a screenshot of it (e.g., saving to `static/screenshots/{papername}_feedback_iter{n}.png`).** The task completes when Gemini responds with "looks good".
    *   **Caching:** Cacheable based on input HTML content hash and task code.

4.  **`task_save_final_html`**:
    *   **Input:** Final HTML content string, Paper name.
    *   **Output:** Path to the saved final HTML file (e.g., `static/sites/{papername}.html`).
    *   **Action:** Writes the final HTML content to the designated file system location. This is necessary for tasks that operate on the file system, like taking the final screenshot.
    *   **Caching:** Cacheable based on input HTML content hash and task code.

5.  **`task_extract_metadata`**:
    *   **Input:** Final HTML content string, PDF file path, Paper name.
    *   **Output:** A dictionary containing extracted metadata (site title, authors, PDF title, publication date, PDF path).
    *   **Action:** Consolidates metadata extraction logic from `site_utils.py` (using BeautifulSoup for HTML title, PyPDF2/Gemini for PDF metadata).
    *   **Caching:** Cacheable based on input HTML content hash, PDF content hash, and task code.

6.  **`task_update_index`**:
    *   **Input:** A list of metadata dictionaries generated by `task_extract_metadata` for all processed papers in a flow run.
    *   **Output:** Modifies the `src/lib/sites.json` file.
    *   **Action:** Loads the existing `sites.json`, merges the new/updated site entries based on the collected metadata, sorts the list, and writes it back to the file.
    *   **Caching:** Cacheable based on input metadata list hash and task code.

## Workflow Orchestration (Prefect Flows)

Two main flows will orchestrate these tasks:

1.  **`create_sites_flow`**:
    *   **Purpose:** Generates new sites or regenerates existing ones from PDF inputs.
    *   **Inputs:** List of PDF file paths, `incremental` boolean flag.
    *   **Logic:**
        *   Iterates through the provided PDF paths.
        *   Optionally skips processing a paper if `incremental` is true and the paper already exists in `sites.json`.
        *   For each paper to process, it calls `task_generate_initial_html`, `task_fix_links`, `task_run_feedback_loop`, `task_save_final_html`, `task_extract_metadata` in sequence. Prefect handles dependencies and caching.
        *   Collects the output (metadata dictionaries) from all `task_extract_metadata` calls within the flow run.
        *   Finally, calls `task_update_index` once with the collected metadata to update `sites.json`.

    ```mermaid
    graph TD
        subgraph Process Paper (Loop)
            A[Input: PDF Path] --> T1(Task: Generate Initial HTML);
            T1 --> T2(Task: Fix Links);
            T2 --> T3(Task: Run Feedback Loop<br/>+ Intermediate Screenshots);
            T3 --> T4(Task: Save Final HTML);
            T4 --> T5(Task: Take Final Screenshot);
            T4 --> T6(Task: Extract Metadata);
            T6 --> C((Collect Metadata Result));
        end

        subgraph Finalize Run
            C --> T7(Task: Update Index);
            T7 --> O[Output: Updated sites.json];
        end

        style T1 fill:#lightblue,stroke:#333
        style T2 fill:#lightblue,stroke:#333
        style T3 fill:#lightblue,stroke:#333
        style T4 fill:#lightgreen,stroke:#333
        style T5 fill:#lightyellow,stroke:#333
        style T6 fill:#lightcoral,stroke:#333
        style T7 fill:#orange,stroke:#333
    ```

2.  **`update_metadata_flow`**:
    *   **Purpose:** Updates metadata for existing sites without regenerating the HTML or screenshots.
    *   **Inputs:** Optional list of paper names (if empty, processes all entries in `sites.json`).
    *   **Logic:**
        *   Loads the current `sites.json`.
        *   Identifies the papers to process based on the input list or by selecting all.
        *   For each selected paper, it reads the existing final HTML content and retrieves the PDF path.
        *   Calls only `task_extract_metadata` using the existing HTML and PDF.
        *   Collects the output (metadata dictionaries) from all `task_extract_metadata` calls.
        *   Finally, calls `task_update_index` once with the collected metadata to update `sites.json`.

    ```mermaid
    graph TD
        subgraph Process Paper (Loop)
            A[Input: Paper Name(s)] --> L{Load sites.json};
            L --> F{Find HTML & PDF Paths};
            F --> R{Read Final HTML};
            R --> T6(Task: Extract Metadata);
            T6 --> C((Collect Metadata Result));
        end

        subgraph Finalize Run
            C --> T7(Task: Update Index);
            T7 --> O[Output: Updated sites.json];
        end

        style T6 fill:#lightcoral,stroke:#333
        style T7 fill:#orange,stroke:#333
    ```

## Code Structure

*   `agents/pipeline/`: New directory for workflow code.
*   `agents/pipeline/tasks.py`: Contains Prefect `@task` definitions.
*   `agents/pipeline/flows.py`: Contains Prefect `@flow` definitions.
*   `agents/pipeline/config.py` (Optional): For constants like prompts, model names, paths.
*   `agents/site_utils.py`: Refactored to contain only core utility functions.
*   `run_pipeline.py`: New command-line entry point script to trigger flows.
*   `agents/create_site.py` (Original): To be removed.
*   `agents/add_titles.py` (Original): To be removed.

## File Locations

*   Input PDFs are assumed to be in a directory like `papers/` relative to the project root.
*   Final generated HTML files will be saved to `static/sites/`.
*   Screenshots (both intermediate feedback loop and final) will be saved to `static/screenshots/`.
*   The site index is `src/lib/sites.json`.

This design provides a robust, observable, and efficient way to manage the site generation and metadata update process, allowing for targeted re-runs when pipeline components are modified.
